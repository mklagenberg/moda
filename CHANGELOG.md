# Changelog

All notable changes to MODA are documented here.

MODA follows Semantic Versioning. A fix is released as a PATCH version when it adds no required behavior.

## [Unreleased]

No unreleased changes.

## [1.0.0] - 2026-08-12

First public contract of Methodology Organization, Design & Audit.

### Added

- Initial MODA 1.0 framework specification, constitution, taxonomy, design model, repository contract, and governance documentation.
- Machine-readable manifest and JSON Schema.
- Evidence-based conformance profile and immutable self-audit history.
- Deterministic repository validator, tests, and GitHub Actions validation workflow.
- Reusable disclosure, manifest, conformance, and audit templates.
- Minimal methodology example with an explicit unknown conformance claim.
- Versioned MODA operational skill, procedural references, provenance manifest, and installation lock example.
- Decision Records for identity, client-zero adoption, repository interfaces, versioning, non-transitive conformance, and skill synchronization.
- Source topology and distribution boundaries, scaffold profiles and generated-file ownership, portable skill adapters, first-activation update awareness, and roadmap governance.
- Root roadmap with portable ChatGPT, Claude, and other host skill packages as the first active outcome.
- Composition, scaffolding, distribution, and runtime update contracts with reusable templates.
- Specification-driven Change Sets, impact schema, differential validator, Git/release workflow, and pull-request template.
- Decision Records for substantive change control and non-circular release evidence.
- Decision policy and coverage audit, including records for agent shims, deterministic validation, release gates, public language, licensing, and v1 conformance profiles.
- Canonical `CLAUDE.md` discovery shim with scaffold and minimal-example counterparts.
- Deterministic release validator and MCP-only human handoff template for exact tag, branch, title, and changelog-derived description.

### Changed

- Returned the client-zero claim to `mapped` and `partial` while the expanded pre-release contract is implemented and audited.
- Required literal evolution artifacts instead of allowing generic documentation mappings to satisfy changelog, roadmap, or Decision Record controls.
- Required operational and normative changes to declare SemVer impact, affected contract surfaces, validation, migration, and recovery.
- Required a mapped validation policy, deterministic repair-and-rerun evidence, and class-specific PATCH, MINOR, and MAJOR release gates.
